### 3. BUSINESS LOGIC & CORE ALGORITHMS

#### A. Donor Eligibility Service
Implement an automated eligibility validator:
- **Age:** Must be between 18 and 65 years old (calculated from `donors.date_of_birth`).
- **Weight:** Must be $\ge 50$ kg.
- **Hemoglobin Level:** Must be $\ge 12.5$ g/dL (from `medical_info.hemoglobin_level`).
- **Recovery Period:** Cooldown since `last_donation_date`:
  - `WHOLE_BLOOD`: at least 90 days.
  - `PLATELETS` / `PLASMA`: at least 14 days.
- Return boolean status and clear validation rejection messages.

#### B. Blood Compatibility Matrix
Create a lookup table mapping recipient blood groups to compatible donor blood groups:
- `O_MINUS`: [O_MINUS]
- `O_PLUS`: [O_MINUS, O_PLUS]
- `A_MINUS`: [O_MINUS, A_MINUS]
- `A_PLUS`: [O_MINUS, O_PLUS, A_MINUS, A_PLUS]
- `B_MINUS`: [O_MINUS, B_MINUS]
- `B_PLUS`: [O_MINUS, O_PLUS, B_MINUS, B_PLUS]
- `AB_MINUS`: [O_MINUS, A_MINUS, B_MINUS, AB_MINUS]
- `AB_PLUS`: All blood groups (Universal Recipient)

#### C. Intelligent Real-Time Matching Engine
When a recipient creates a blood request:
1. **Hard Filters:**
   - Donor must match compatibility list for the requested blood group.
   - `donors.availability_status == 'AVAILABLE'`.
   - Donor must pass the Eligibility Service check.
2. **Spatial Distance Calculation:**
   - Implement the Great-Circle Haversine Formula between `(blood_requests.latitude, blood_requests.longitude)` and `(donors.latitude, donors.longitude)`.
   - Perform progressive radius expansion: Search initially within 10 km; if $< 3$ candidates found, expand to 25 km, then to 50 km.
3. **Composite Scoring Formula:**
   For each eligible candidate within the radius:
   $$\text{DistanceScore} = \frac{1}{1 + \text{distance\_km}}$$
   $$\text{ReliabilityScore} = \frac{\text{completed\_donations}}{\max(\text{total\_matches}, 1)}$$
   $$\text{RecencyPenalty} = \text{Penalty scalar (0.0 to 1.0 based on how close donor is to cooldown threshold)}$$
   $$\text{BaseScore} = (0.5 \cdot \text{DistanceScore}) + (0.3 \cdot \text{ReliabilityScore}) + (0.2 \cdot \text{RecencyPenalty})$$
   Apply Urgency Multiplier:
   - `EMERGENCY`: $1.5\times$
   - `URGENT`: $1.2\times$
   - `NORMAL`: $1.0\times$
   $$\text{FinalScore} = \text{BaseScore} \cdot \text{UrgencyMultiplier}$$
4. **Ranking & Dispatch:**
   - Sort candidates descending by `FinalScore`.
   - Persist matches in `donor_match`.
   - Dispatch mock notification (log dispatch to console/DB) and flag `is_notified = True`.

#### D. Inventory Health & Expiry Scanning Engine
- **Status Calculation:** Map stock-to-minimum-threshold ratios:
  - Ratio $> 50\% \rightarrow$ `HEALTHY`
  - $20\% \le \text{Ratio} \le 50\% \rightarrow$ `LOW_STOCK`
  - Ratio $< 20\% \rightarrow$ `CRITICAL`
  - Ratio $= 0 \rightarrow$ `OUT_OF_STOCK`
- **Manual / Cron Trigger Endpoint:**
  - `POST /api/inventory/scan-expiries`: Queries all inventory records where `expiry_date <= CURRENT_DATE + INTERVAL '72 hours'`, updates their alert state, and logs system warnings.

### 4. API ENDPOINT SPECIFICATIONS (RESTful JSON)

Organize routes into clear APIRouters:

- **`/api/v1/auth`**
  - `POST /register`: Register user with role (`DONOR`, `RECIPIENT`, `HOSPITAL_ADMIN`, `SYSTEM_ADMIN`). Atomically creates the child profile (`donors`, `recipients`, or `hospitals`).
  - `POST /login`: Authenticates user; returns Access Token and sets secure Refresh Token.
  - `POST /refresh`: Validates refresh token and returns new token pair.
  - `GET /me`: Returns authenticated user profile with related role-specific profile data.

- **`/api/v1/donors`**
  - `PUT /profile`: Update donor personal data, address, and coordinates.
  - `PATCH /availability`: Toggle between `AVAILABLE` and `UNAVAILABLE`.
  - `GET /eligibility`: Run automated eligibility check against donor's current records.
  - `POST /medical-info`: Upsert medical details.
  - `GET /history`: Fetch donor's historical donation log.

- **`/api/v1/requests`**
  - `POST /`: Create blood request. Triggers matching engine automatically.
  - `POST /emergency`: High-priority endpoint that bypasses queues, expands radius immediately to 50 km, and flags request as `EMERGENCY`.
  - `GET /`: List requests with filters (`blood_group`, `urgency`, `status`).
  - `GET /{request_id}`: Request details.
  - `GET /{request_id}/matches`: Returns matched donors (with personal contact info masked).

- **`/api/v1/matches`**
  - `POST /{match_id}/respond`: Donor accepts or declines (`ACCEPTED` or `DECLINED`).
  - `GET /{match_id}/contact`: Returns donor contact information (phone, address, email) ONLY IF `response_status == 'ACCEPTED'`. Otherwise, raises HTTP 403 Forbidden.

- **`/api/v1/inventory`**
  - `GET /`: Get current hospital blood inventory with status indicators.
  - `POST /transaction`: Record stock transaction (`IN`, `OUT`, `ADJUSTMENT`). Automatically updates `blood_inventory.quantity` and recalculates `status`.
  - `POST /scan-expiries`: Triggers 72-hour expiry monitor sweep.

- **`/api/v1/appointments`**
  - `POST /`: Book donation appointment at a hospital center.
  - `GET /my-appointments`: List appointments for authenticated donor or hospital.
  - `PATCH /{appointment_id}/status`: Update status (`COMPLETED`, `CANCELLED`).

- **`/api/v1/events`**
  - `POST /`: Create donation campaign/event (Hospital/System Admin).
  - `GET /`: List upcoming events.
  - `POST /{event_id}/register`: Donor registers for an event.
  - `POST /{event_id}/checkin`: Check in a participant.

- **`/api/v1/campaign-notices`**
  - `GET /`: Public campaign notices.
  - `POST /`: Create notice (Admin only).

- **`/api/v1/system-logs`**
  - `GET /`: Read audit logs (System Admin only).
